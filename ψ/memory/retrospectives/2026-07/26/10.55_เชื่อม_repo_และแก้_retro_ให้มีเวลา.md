## Honest Feedback

1. friction แรกคือผมใช้สมมติฐานจาก skill เดิมมากเกินไป Skill `/rrr` บอกให้หา `.jsonl` จาก `~/.claude/projects` ซึ่งถูกใน Claude Code context แต่ไม่พอสำหรับ Codex runtime รอบนี้ ถ้าผู้ใช้ไม่กำชับ ผมอาจปล่อย retrospective แบบ “timestamps unavailable” ทั้งที่ข้อมูลมีอยู่จริงใน `~/.codex/sessions` นี่เป็น friction เชิง runtime ไม่ใช่ความเป็นไปไม่ได้

2. friction ที่สองคือ workspace เริ่มจาก zip download ทำให้ตอนแรก root อยู่ผิดระดับ ผมเขียน retro รอบแรกไว้ที่ parent folder เพราะตอนนั้นยังไม่รู้ repo จริงอยู่ใน `devjosh-oracle-main/` พอผู้ใช้ชี้ repo GitHub มา ผมจึงเชื่อมถูกที่ แต่ผลคือมี memory สองที่: fallback เก่าใน parent และ retro ใหม่ใน repo จริง เรื่องนี้ควรถูกบอกตรง ๆ เพื่อไม่ให้ session memory กระจัดกระจาย

3. friction ที่สามคือ parser ของผมรอบแรกอ่าน Codex JSONL ไม่ออก เพราะผมหาเฉพาะ shape แบบ `message.role=user` แล้วไม่ได้ดู `event_msg.payload.type=user_message` ตั้งแต่แรก ผมแก้ด้วยการ inspect record จริง แต่เสียเวลาไปหนึ่งรอบ และทำให้เห็นว่าการ “อ่าน format จริงก่อนเขียน parser” ควรเป็นนิสัยถาวร

## Lessons Learned

- ถ้า retrospective ต้องมีเวลา ให้ค้น session logs ตาม runtime จริงก่อน: Claude ใช้ `~/.claude/projects`, Codex ใช้ `~/.codex/sessions`
- ก่อนเขียน memory ให้ยืนยัน repo root ที่ผู้ใช้ตั้งใจใช้ ไม่ใช่แค่ `pwd` ที่ session เปิดมา
- ถ้า parser อ่าน log ไม่เจอข้อความผู้ใช้ ให้ inspect JSONL record จริงก่อนสรุปว่าไม่มีข้อมูล
- zip download ที่เพิ่งผูก Git ต้องระวังไฟล์ local-only เช่น `.envrc` และอย่าทับ working tree ระหว่างเชื่อม remote
